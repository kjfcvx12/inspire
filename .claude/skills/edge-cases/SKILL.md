name: edge-cases
description: 입력 유형별 엣지 케이스를 도출해 테스트로 만들고 '죽음 / 조용한 오답 / 명확한 오류'로 분류해 고친다. 핵심 기능 완료 후와 발표 전 검증 단계에서 사용.
---

목적: 데모에서 면접관이 이상한 입력을 넣어도 앱이 죽거나 그럴듯한 오답을 내지 않게 한다. 작업 폴더는 `projects/<이름>/`.

1. 입력 유형을 나열한다(자유 텍스트 / 숫자 / CSV·DataFrame / 파일 / 선택값).
2. 공통 입력부터 쓴다: `common/edgecases.py`의 `TEXT_EDGES`, `NUMBER_EDGES`, `frame_edges(df, target)`.
3. 도메인 특화 엣지를 3~5개 더한다. 예: 문서에 없는 질문, 모순된 문서, 범위를 벗어난 값, 학습에 없던 범주, 한글·영문 혼합.
4. `tests/`에 파라미터화 테스트를 추가한다. 기대값은 "예외 없이 str을 돌려줌"처럼 약하게 시작해, 의미 있는 항목은 강하게 만든다.
5. 실행해서 결과를 세 가지로 분류한다.
   - **죽음**(예외/타임아웃): 버그. 고친다.
   - **조용한 오답**(그럴듯하지만 틀림, 빈 입력에 답을 지어냄): 가장 위험. 입력 검증이나 "모르겠다" 경로를 만든다.
   - **명확한 오류**(안내 메시지와 함께 거절): 정상. 메시지가 사용자에게 읽히는지만 본다.
6. 고친 것은 회귀 테스트로 남기고, 의미 있는 결정은 `docs/decisions.md`에 한 줄 적는다.
7. 프롬프트 주입 문장(`TEXT_EDGES`에 포함)에서 시스템 프롬프트·키·내부 경로가 노출되지 않는지 눈으로 확인한다.

보고 형식: 입력 유형 · 확인한 엣지 수 · 죽음/조용한 오답/명확한 오류 건수 · 고친 것 · 남은 위험(미확인 포함).
