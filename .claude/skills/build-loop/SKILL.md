기능 하나(또는 오류 하나)에 대해 아래 루프를 돈다. 대상: $ARGUMENTS

0. **완료 조건**을 한 줄로 정한다. 반드시 실행 가능한 검사(명령 + 기대 결과, 또는 테스트·골든 입력)여야 한다. 없으면 먼저 만든다.
1. **가장 작은 조각**만 구현한다(15분 이내).
2. `python scripts/check.py`와 해당 기능을 실제로 실행한다.
3. 실패하면 에러 전문을 읽고 **가설 1개 → 최소 수정 → 재실행**. 추측으로 여러 곳을 동시에 고치지 않는다.
4. 통과하면 `/checkpoint`로 저장하고 다음 조각으로 간다.

## 실험·비교 규칙 (리허설에서 발견)
- 모델 비교·임계값 스윕·성능 측정은 일회성 `python -c`로 끝내지 않고 `scripts/`에 파일로 남기고 결과를 `docs/evidence.md`에 저장한다(발표 근거).
- 작은 홀드아웃 하나로 "효과 없음" 같은 결정을 내리지 않는다. 교차검증으로 재확인하고, 결정을 뒤집었으면 이전 결정과 이유를 `decisions.md`에 남긴다.
- `decisions.md`의 시각은 추측하지 말고 실제 시각(`date`, `python scripts/start.py`)으로 적는다.

## 종료·탈출 조건
- 같은 증상 3회 실패 또는 15분 경과 → **접근을 바꾼다**(다른 방법, 범위 축소, mock). 바꾼 이유를 `docs/decisions.md`에 한 줄 적는다.
- 원인을 모르겠으면 코드를 더 고치지 말고 최소 재현(입력 1개)부터 만든다. 서로 다른 시도를 병렬로 하고 싶으면 `verifier` 에이전트에 독립 검증을 맡긴다.
- 루프가 시간표(`/timecheck`)를 넘기면 즉시 중단하고 범위를 줄인다.

## 출력 형식 (고정)
루프마다 한 줄: `시도 N: 가설 → 변경 → PASS/FAIL(근거)`. 마지막에 `## 결과` 3줄 이내(완료 조건 충족 여부, 시도 횟수, 남은 위험).

## 검증
- "고쳤다"는 실행 결과로만 말한다. 실행하지 않은 수정은 "미확인"이다.
