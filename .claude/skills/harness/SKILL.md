하네스 = 결과물이 맞는지 **자동으로·반복해서** 확인하게 해 주는 바깥 구조. 구현 전에 10분 안으로 최소한만 만든다.

## 점검·구축 순서
1. **검사 한 방**: `python scripts/check.py`가 PASS/WARN/FAIL을 내는지 확인한다. 주제에 맞는 검사 항목이 필요하면 추가한다.
2. **골든 케이스**: `tests/test_golden.py`에 입력→기대 결과 3~5개(정상 흐름 1, 엣지 2 이상)를 만든다. 주제가 정해지면 가장 먼저 쓴다.
3. **폴백**: 키 없음·API 실패 시 mock으로 같은 화면·흐름이 나오는지 확인한다.
4. **가드레일**: 에이전트 반복 한도, `max_tokens`, 타임아웃, 입력 검증, 빈 입력 처리.
5. **관찰 가능성**: 최소한 호출 입출력을 로그로 남긴다. 키가 있으면 Langfuse(선택)를 쓴다.
6. **권한·비밀**: `.claude/settings.json`의 allow/deny, `.env`가 커밋되지 않았는지.

## 테스트 품질 규칙 (리허설에서 발견)
- 반환 타입·범위만 보는 테스트는 틀린 모델을 못 잡는다. 값이나 **방향**(악성 표본의 확률이 높은가 등)을 단언한다.
- 엣지 케이스에 빈 입력 외에 NaN, 음수, 극단값(1e12), 문자열, 전부 0을 포함한다. 조용히 예측되면 입력 검증을 추가한다.
- 변이 테스트: 핵심 로직을 일부러 뒤집어(라벨·열 반전 등) 테스트가 FAIL 나는지 확인한 뒤 되돌린다.
- 데모 표본이 학습 데이터와 겹치지 않는지, 겹치면 화면에서 구분되는지 확인한다.

## 출력 형식 (고정)
6개 항목을 `✅/❌ 항목 — 근거(명령·결과)` 한 줄씩. ❌는 만든 뒤 재확인한 결과를 덧붙인다. 전체 15줄 이내.

## 검증
- 하네스가 실제로 실패를 잡는지 한 번 확인한다(예: 골든 기대값을 일부러 틀리게 해 FAIL이 나는지).
