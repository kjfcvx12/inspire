---
name: timecheck
description: 시간표 대비 진행 상황을 점검하고, 뒤처졌으면 무엇을 버릴지 제안한다. 면접 중 수시로(대략 20분마다, 막혔을 때) 사용.
---

1. 시작 시각: 작업 폴더(`projects/<이름>/`)의 `docs/decisions.md`의 `START` 줄. 키트 루트의 `docs/decisions.md`는 템플릿이라 `(HH:MM)`으로 비어 있으니 읽지 않는다. 작업 폴더가 없거나 값이 `(HH:MM)`이면 그때만 한 번 사용자에게 시작 시각을 묻는다(핵심 정보). 기록 시각은 분 단위라 경과는 ±1분이다.
2. 현재 시각을 명령으로 확인하고 경과 분을 계산한다. 추측하지 않는다.
3. 단계 기준(누적 분): 분석 0~10 · 설계 10~20 · 구현 20~85 · 검증 85~95 · 발표 준비 95~110 · 여유 110~120.
4. 진행률: `/plan`의 MVP "반드시" 항목 중 실제로 동작을 확인한 개수 / 전체.
5. 판정: 경과 대비 진행률이 뒤처지면 "시간 남으면" 항목부터, 그래도 모자라면 "반드시" 항목의 축소안을 제안한다.

## 규칙
- 85분에 기능 동결. 이후 코드 변경은 버그 수정만 허용한다. 100분이 절대 한계이며 이후는 발표 준비만 한다.
- 범위 축소는 제안만 하고, 방향이 바뀌는 큰 축소만 사용자에게 확인한다.

## 출력 형식 (고정)
`## 지금 / ## 계획 대비 / ## 자를 것 / ## 다음 10분` 4개 헤더, 12줄 이내. 지금: 경과 N분 · 단계 · 남은 분.

## 검증
- 완료로 센 항목은 실행해서 확인한 것만. 미확인은 "미확인"으로 표기하고 완료로 세지 않는다.
