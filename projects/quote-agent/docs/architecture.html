용역 견적 에이전트 — 아키텍처

서울대 연구행정시스템 PI 용역을 기준으로, 다른 대학의 변형 요청(기한·인원·범위·옵션)을 견적으로 비교해 보여주는 웹서비스. 핵심 원칙: 해석·설명은 LLM, 금액 계산은 파이썬 엔진, 설명 속 금액은 검증기가 대조.

2. 요청 한 건의 흐름

  1. 입력 — 폼 제출(app.py). 빈 입력은 경고, 시연 저장본이 켜져 있으면 replay.lookup으로 즉시 반환.
    Streamlit · session_state
  2. 해석·도구 선택 — agent.run이 llm.create(tools=TOOLS)를 호출. 모델이 조건을 구조화해 도구를 부름.
    anthropic · tenacity 재시도 · 실패 시 mock
  3. 검증 — 도구 인자를 QuoteRequest로 파싱(범위·중복·충돌 거부). 대학 별칭은 client_aliases로 정규화.
    pydantic v2 validators
  4. 계산 — engine.calculate 결정적 계산. 기준안 대비 diff, 필요하면 right_size_team/fit_to_budget.
    순수 파이썬, LLM 없음
  5. 결과 회신 루프 — 도구 결과(JSON)를 모델에 돌려 최대 8회까지 반복, 마지막에 설명문 작성.
    반복 한도 도달 시 계산된 범위까지만 표시
  6. 금액 대조 — verify.unverified_amounts가 설명문 금액을 엔진 결과와 비교, 불일치는 '미검증'.
    정규식 기반, 길이 상한에도 지연 없음
  7. 표시·저장 — 탭별 렌더, 엑셀 생성, 이력 저장(SQLite), 사용량 기록(JSONL).
    pandas · openpyxl · sqlite3

5. 핵심 설계 결정 (이유 한 줄)

  • 금액은 파이썬 엔진이 계산 — 숫자는 테스트로 재현·검증돼야 하므로 LLM에 맡기지 않음.
  • 설명 속 금액을 엔진 결과와 대조 — 모델이 반올림·지어낸 금액을 화면에서 '미검증'으로 드러내려고.
  • 도구 호출 루프 직접 구현 + 반복 한도 — 프레임워크 없이 동작을 설명·통제할 수 있고, 무한 루프를 막음.
  • 호출은 common.llm 한 곳 경유 — 재시도·mock 폴백·비용 기록을 한곳에서 보장.
  • 단가·비중은 assumptions.json로 분리 + 버전 기록 — 공개 정보가 없어 가정이므로 숨기지 않고, 실제 견적서를 받으면 파일만 교체.
  • 민감 건은 AI 끄기 모드 — 요청 문장을 외부로 보내지 않고 규칙 파서로만 처리.

6. 알려진 한계·불일치 (코드 확인 결과)

  • openpyxl이 requirements.txt에 없음 — 엑셀 내보내기가 쓰는데 현재 환경에는 설치돼 있어 동작. 새 환경에서는 설치 누락 위험.
  • 키트의 common/db · structured · textsearch · docloader · embedsearch는 이 앱에서 사용하지 않음 (검색 평가 스크립트만 일부 사용).
  • .env.example의 Langfuse·Supabase 항목은 아직 코드에 연결되지 않음.
  • 단가·기준안은 모두 가정값, 견적은 담당자 검토 전 초안.
  • 에이전트 골든셋 통과율은 실행마다 달라질 수 있음 (같은 날 17/18~18/18 관찰).
  • 실행 환경 Python은 3.12.15 (프로젝트 문서의 3.11과 다름).
