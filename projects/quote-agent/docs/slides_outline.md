# Canva 슬라이드 원고 (9장, 동결 후 수치 확인하고 게시)
문체 원칙: 사람이 말하듯 짧게 쓴다. "~를 제공합니다", "강력한", "혁신적인", 이모지, 같은 틀로 세 개씩 나열하기는 쓰지 않는다. 숫자는 확인된 것만 쓴다.
수치 갱신 대상: 6장(테스트 수, 평가 결과, 비용). 15:17 기준값이며 15:35 동결 후 다시 확인한다.

## 1. 제목
**용역 견적 에이전트**
같은 용역을 대학마다 처음부터 다시 계산하던 일을 줄여 봤습니다.
2시간 안에 만든 프로토타입

## 2. 문제
서울대에 낸 견적이 있어도 고려대나 연세대에 내려면 다시 계산해야 합니다. 기간도 인원도 범위도 조금씩 다르기 때문입니다.
조건을 바꿀 때마다 총액이 얼마나 달라지는지, 어디서 인력이 모자라는지를 바로 보기 어렵습니다.

## 3. 만든 방식
(구조도) 요청 문장 → 에이전트 → 계산 엔진 → 금액 검증 → 화면
한 줄 요약: 계산은 코드가 하고, AI는 요청을 읽고 설명만 합니다.

## 4. 제가 정한 것
- 금액은 AI에게 맡기지 않았습니다. 같은 입력이면 같은 금액이 나와야 하고, 틀리면 테스트로 잡을 수 있어야 해서입니다.
- AI가 설명에 쓴 금액은 엔진이 낸 값과 맞는지 한 번 더 대조합니다.
- API가 안 될 때를 위해 규칙 기반 대체 동작을 뒀고, 화면에 그렇다고 표시합니다.
- 버린 것: 공개 입찰 공고로 단가를 맞추는 일. 공고에는 추정가격만 있어서 단가의 근거가 되지 못했습니다.

## 5. 데모
"고려대에서 같은 용역을 3개월에 5명으로 요청했어. 견적 보여줘"
기준안 353,560,000원과 비교한 표, 인력 경고, 도구 호출 기록을 보여 줍니다.
(실행 화면 캡처는 동결 후 1장 넣는다)

## 6. 확인한 결과
- 테스트 136개 통과
- 에이전트 평가 18/18. 오늘 5회 실행 결과는 18, 17, 18, 17, 18건(18건 중)이라 5회 중 3회 만점이었고, 실패는 매번 다른 사유여서 조사 후 고쳤습니다. 표본이 적어 비율(%)로는 표시하지 않습니다. 다만 같은 세트가 한 번은 17건이었고, 시험 문제를 보고 고친 것이라 일반화된 정확도로 보기는 어렵습니다.
- API 비용은 평가까지 합쳐 지금까지 약 $2(평가와 시연 저장본 생성 포함), 호출당 약 $0.007

## 7. 한계
- 단가와 대학별 규모 계수는 공개된 정보가 없어서 전부 가정한 값입니다. 화면에 그대로 적어 두었고, 설정 파일로 빼서 실제 단가표로 바꿀 수 있게 했습니다.
- 그래서 금액 자체보다 조건이 바뀔 때의 차이와 경고가 이 도구가 주는 것입니다.
- 지금은 제 PC에서 돌리는 웹 앱이고, 배포하지는 않았습니다.
- 요청 문장과 계산 결과는 외부 API로 나갑니다. 결과는 가정값으로 만든 초안이라 그대로 견적서로 쓰면 안 됩니다.

## 8. AI를 쓰면서 틀렸던 것
- 대체 동작이 요청한 인원과 다른 팀을 만들었습니다. 테스트를 붙여 고쳤습니다.
- 검색 요약에 있던 낙찰률 수치가 원문에 없어서 쓰지 않았습니다.
- 모델이 초과 금액을 "약 4,600만 원"처럼 둥글게 말했는데 검증 단계가 잡았고, 프롬프트에서 반올림을 막았습니다.
- 대체 동작이 "상주 없음"을 상주로 읽었습니다. 면접관 역할 에이전트로 점검하다 찾았고 고쳤습니다.
- 별도 검증 에이전트를 세 번 돌렸고 매번 새 결함이 나왔습니다. 대체 동작의 입력 해석 오류, 금액 검증의 허점("4억"을 통과시킴), 엑셀 내려받기의 수식 주입을 테스트부터 붙여 고쳤습니다.

## 9. 다음에 한다면
실제 발주처 양식에 맞춘 출력(지금은 우리 형식의 엑셀 초안까지), 실제 과거 견적서로 단가를 보정하고, 문장을 파라미터로 바꾸는 정확도를 더 많은 문장으로 재고 싶습니다.
이제 직접 돌려 보겠습니다. (로컬 앱으로 전환: 발표 전에 `scripts\demo_start.ps1` 실행해 두기)
