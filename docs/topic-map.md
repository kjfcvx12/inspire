# 예상 주제 → 스타터 매핑 (2.md·1.md 반영, 참고용)

주제는 당일 공개된다. 아래는 2.md에 나온 후보를 어느 스타터로 시작할지 미리 정해 둔 것일 뿐 확정이 아니다. 5번 주제는 자료에 없다.

| # | 주제 | 시작 타입 | 핵심 MVP | 주의 |
|---|---|---|---|---|
| 1 | 패션 트렌드 감지 | `rag` | 해시태그 입력 → 샘플 게시물 JSON을 LLM이 분석해 리포트 | 크롤링 안 함. 샘플 데이터 출처를 밝힌다 |
| 2 | 주식 신호등 | `rag` | 뉴스 감성 분석 → 신호등 색 | 실시간 피드는 네트워크 의존 → **캐시된 뉴스로 폴백**. 주가는 더미임을 명시 |
| 3 | 여행 원스톱 예약 | `rag`/`blank` | 자연어 → 구조화 일정(`structured`) | 예약 링크는 가상임을 명시 |
| 4 | 투수 제구 확률 | `predict` | 경기 상황 → 확률 | **`random` 값 금지.** 최소한 샘플 데이터를 만들어 학습·평가하고, 합성 데이터라고 밝힌다. 영상 파싱은 mock |
| 6 | 리조트 메뉴 수요 | `predict` | 날씨·온도·동행 유형 → 메뉴별 수요, 식자재 환산 | 위와 동일. 합성 데이터의 한계를 말한다 |

## 발표 방어 문구 (2.md에서 가져와 정직하게 수정)
"2시간 안에 비즈니스 가치와 데이터 흐름을 검증하려고 무거운 부분(영상 파싱, 실시간 시세, 대규모 모델 서빙)은 mock/샘플로 추상화했습니다. 어디가 mock이고 어디가 실제 동작인지 표로 구분했고, 수치는 `scripts/eval.py`로 재현됩니다. 프로덕션이면 [실데이터 수집, 모델 서빙, 입력 검증, 상태 영속화]가 다음 과제입니다."
- 핵심은 "mock을 숨기지 않고 경계를 밝히는 것"이다. 한계 인정 + 고도화 피칭 구조는 `/present`의 "결과·한계"에 넣는다.
